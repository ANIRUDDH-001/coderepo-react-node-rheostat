# Rheostat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Rheostat, a feature-flag and progressive-delivery platform (React + Express + MongoDB) that passes the HackerRank Code Repo validator from a clean checkout.

**Architecture:** Feature-folder monorepo mirroring the reference calendar: `route → controller (Zod) → service (rules) → repository (Mongoose)` on the backend, `features/<domain>/` + `shared/` on the frontend with a hand-rolled History router. All decision logic (evaluator, config diff, change-request transitions, rollout planning and reconciliation, lifecycle, permissions) lives in pure modules with `bun test` coverage; services are thin orchestration over repositories.

**Tech Stack:** Bun workspace; React 19.2.4, Vite 8.2.2, @vitejs/plugin-react 6.1.1, @fontsource/roboto 5.3.0; Express 5.2.1, Mongoose 8.24.1, Zod 4.3.6, jsonwebtoken 9.0.2, bcryptjs 3.0.2, cors 2.8.6, dotenv 17.3.1; concurrently 9.2.1; MongoDB 8 on 127.0.0.1:27017; `bun test` (built in).

**Spec:** `docs/superpowers/specs/2026-09-18-rheostat-design.md` — every task below implements a numbered section of it; read the section before starting the task.

## Global Constraints

- Exactly the reference dependencies at exactly the reference versions listed above. No additions, replacements, or upgrades. The only manifest changes: package names/descriptions, and `"test": "bun test"` scripts.
- Frontend port `3000`, backend port `8000`, MongoDB `mongodb://localhost:27017/rheostat_db`. `hackerrank.yml` install `bun install && bash setup.sh --seed`, run `bun start`. Start reseeds.
- No WebSockets, uploads, email, external services, external media, CDN assets, regex targeting, or router/chart/date libraries.
- Prettier config from the reference (`useTabs: true, tabWidth: 4, printWidth: 140, semi, double quotes, trailingComma: all`). `.editorconfig` from the reference. American English everywhere.
- Response envelopes `{ data }` and `{ error: { code, message, details? } }`; errors via `AppError(statusCode, code, message, details)`; never a 500 for invalid input, missing resources, or authorization.
- Every public backend product route must have a reachable frontend consumer in the same or a later phase of this plan; `/api/v1/health` is the only exemption. No route may be left without a consumer at the end of Phase 7.
- Feature folders only; no cross-feature repository access (services call other features' services).
- `localStorage` keys prefixed `rheostat-`; JWT issuer `rheostat-api`, audience `rheostat-app`.
- Copy in UI, seed, and docs must be realistic, inclusive, and free of external brands.
- Commits are made by the user. Tasks end at "verified", and the user is told what changed.

	const page = Math.max(1, Number.parseInt(query.page, 10) || 1);

Implementation:

```js
import { createHash } from "node:crypto";
export function bucketFor(flagKey, environmentKey, value) {
	const digest = createHash("sha1").update(`${flagKey}.${environmentKey}.${String(value)}`).digest("hex");
	return Number.parseInt(digest.slice(0, 8), 16) % 100000;
}
```

**Files:**

- Test: `backend/src/features/rollouts/reconcile.test.js`

**Interfaces:**
- Produces: `createReconciler({ plans, flags, versions, audit, now, staleClaimMs = 120000 }) → { reconcileDue() }` where `plans = { findDue(now), findStaleClaims(before), claimStep(planId, stepId, claimedAt), releaseStep(planId, stepId), markApplied(planId, stepId, appliedVersion), stall(planId, reason), complete(planId) }`, `flags = { findById(id), applyRolloutStep(flagId, envKey, expectedVersion, fallthrough, actorId) → updated | null, currentConfig(flagId, envKey) → { version, enabled, fallthrough } }`, `versions = { insert(doc) → doc, findByStep(planId, stepId) → doc | null }`, `audit = { record(entry) }`. - [ ] Tests with in-memory fakes: applies a due step and advances `expectedVersion`; two reconcilers racing on the same step → exactly one version written; version mismatch → `stalled` with `CONFIG_CHANGED_OUTSIDE_ROLLOUT`, claim released; same-version race → claim released, no stall; kill switch active → step untouched; last step → `completed`; plan `scheduled` → `running` after first step; **recovery**: stale claim with version present → finalized, no second version; stale claim with nothing written → released and applied in the same pass; stale claim with flag advanced but no snapshot → snapshot inserted with `source: rollout` and `actorId = createdBy`, then finalized; stale claim with flag advanced to a different fallthrough → `RECOVERY_AMBIGUOUS`; a fresh claim (< 120 s) is left alone.
